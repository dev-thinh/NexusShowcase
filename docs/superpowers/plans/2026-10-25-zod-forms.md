# Systemwide Zod form validation

All forms must validate with Zod and suppress native HTML5 validation popovers. Reuse feature schemas on the client and server. Keep native input semantics and keyboard hints, but always render noValidate. Show field errors in Vietnamese, mark invalid controls, associate messages and focus the first invalid control. Server validation remains authoritative.

Scope: login, account creation, password change/confirmation, profile and dynamic personal links, publication draft/submission, review feedback, pin replacement, bulk search, admin searches, personal-post search, category and library filters. Use a shared client ValidatedForm and FieldError; server search forms use a serializable SearchForm wrapper with the shared search schema. Preserve Next Form navigation for query forms. Keep success dialogs and request failure messages separate from validation errors.

Verify invalid submissions do not invoke mutations or navigate; test required fields, optional passwords, password mismatch, URL protocols, dynamic links, numeric search filters and a source audit that no native form can show HTML5 popovers. Browser inspection must not create accounts or change existing user data.
