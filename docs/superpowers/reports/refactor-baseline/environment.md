# Navigation baseline environment

Captured 2026-10-21 on Windows_NT 10.0.26200 x64, Node v24.20.0, Intel Core i5-12450H (12 logical CPUs), 16 GiB RAM. Installed Next.js 15.5.27, Prisma 6.19.3 and Playwright 1.64.1. Browser version and exact capture timestamps are recorded in `metrics.json`. Browser viewport: 1440 × 1000; default motion settings; no artificial CPU/network throttling.

The captured baseline uses installed **headless Microsoft Edge 155.0.4283.62**, selected with `HARNESS_BROWSER_CHANNEL=msedge` for both browser journeys and benchmark. Keep that channel/version for comparable after measurements; explicitly label any browser-version change. The full Chromium download completed later; it was not substituted for the baseline engine. Source provenance is the controller's `before-task-2` filesystem snapshot after F1, plus this harness/timing change, on Git HEAD `dde224138ea0409989d71d9a5b5a03ddccd0837a`; the pre-existing working tree was dirty and no commit was created.

The baseline commands in PowerShell were `$env:HARNESS_BROWSER_CHANNEL = 'msedge'; npm.cmd run test:e2e` and `$env:HARNESS_BROWSER_CHANNEL = 'msedge'; npm.cmd run bench:navigation`. The benchmark refuses to append results to a report whose browser channel, version or Node version differs; use a different `outputPath` for those measurements.

Run `npx playwright install chromium --no-shell` with `PLAYWRIGHT_BROWSERS_PATH` set to the workspace's `.playwright` directory, then `npm run test:e2e` or `npm run bench:navigation`. The harness uses the full Chromium headless channel. Database credentials stay in local environment configuration. `TEST_DATABASE_URL` must name a dedicated PostgreSQL test database with an empty, initialized application-schema template and a different database identity from `DATABASE_URL`.

Each command verifies the dedicated database catalog, creates an owned UUID schema, clones only the application schema structure, stages synthetic fixtures, and supplies the scoped test URL explicitly to both `next build` and `next start`. The benchmark rebuilds separately for 20 items / 100 members and 1000 items / 100 members. Startup uses a fresh, locally bound port and probes the auth-provider endpoint. Normal success/error paths stop the server, remove fixture schemas and delete the private temporary credential manifest. The development database is never a harness target.

The benchmark preserves native navigation, prefetch, route caching, UI and application data queries. Each dataset contains four separately labeled cold-browser samples and ten warm samples per route, in research → robotics → members → home order. Cold-browser means a new browser/router context after the entry page is loaded, with native prefetch enabled; the server, OS and database can be warm. These are not cold process or cold database samples. Warm runs reuse one browser context.

Click timing begins at the captured DOM click event. A mutation observer records the pending marker, a visible destination shell with the active navigation tab, then the expected synthetic fixture heading. `clickToDataMs` means **first visible fixture data**, not complete-page or all-data-settled time; complete-page data timing is unavailable. Content failures remain recorded as failed samples and null data timing. The observation timeout is 3.5 seconds; missing shell/data observations are unavailable, not zero. Pending markers can be unobservable when a cached navigation commits immediately.

With `PERF_METRICS=1`, the request-cached auth wrapper and Prisma SQL events emit allowlisted numeric durations and epoch timestamps only. The browser harness assigns a UUID correlation ID to each serial observation window and retains its raw numeric events and window bounds. Window auth/query totals can include prefetch and background work; initial entry-page work before a sample is excluded. Prisma engine callbacks cannot provide reliable exact Next-request attribution here, so request-specific query count/time are explicitly unavailable. A window without query/auth events remains null, even where route caching is the likely cause. Prisma's reported SQL duration can legitimately be zero milliseconds due to engine timer resolution.

RSC bytes are the sum of complete decoded `text/x-component` response bodies observed during a window, including prefetch responses. They are not compressed wire sizes. When no complete RSC body is observable, the metric is null. Summaries use the median and nearest-rank p95 of available warm samples and expose the available sample count. Cold-browser samples stay separate in raw data. No improvement claim is made from this baseline.

Browser traces, screenshots, videos and saved auth states are disabled. Browser/cache/temporary artifacts and error-context files are ignored by Git. Only sanitized numeric metrics and this environment record are intentional report artifacts. Existing Vite CJS deprecation and NO_COLOR/FORCE_COLOR warnings are unrelated to measured product behavior.
