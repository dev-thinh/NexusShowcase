# Full local demo implementation plan

**Goal:** Give the user a running, isolated demonstration covering all post statuses and many member states, without changing the current installation.
**Design:** A new `nexus_showcase_demo` PostgreSQL database with its own restricted runtime role, secret and cookie namespace; Next production preview at loopback port 3002 using `.next-demo`. Keep port 3000/current DB untouched. Seed deterministic create-only entities so reruns retain edits.
**Content:** 60 accounts (all five roles, active/pending/suspended/deleted/forced-password cases); 56 items (all seven ItemStatus values, both types, public/private, pinned and pending-update variants), valid review snapshots/comments/audit, contributor relations, PDF/text resources, missing-media cases, 12 moments and three research photos. Code-generated local technical illustrations/avatars avoid cloud/network mutations.

- [x] Asset fixtures: deterministic SVG-to-PNG diagrams/avatars, valid PDF/text, exclusive safe writes with meaningful tempdir tests.
- [x] Dataset: schema-valid lifecycle combinations, category assignment, multi-author content, gallery/library, idempotency integration tests.
- [x] Guarded provisioning and seed CLI; no resets, no runtime URL edits, separate private demo config.
- [x] Production preview launcher with loopback binding, separate build directory and cookie names.
- [x] Type/architecture/unit/integration checks; production demo startup and browser login/public/private/review/status checks; final guide with URL and demo credentials.

Known choice: READY_FOR_APPROVAL and EDITOR are included as labeled legacy examples because the current direct-admin workflow no longer generates them. ACHIEVEMENT is also a legacy type outside the two current publication categories; do not create misleading unsupported category behavior.

Final unit run includes additional guard cases. URL/status guide: docs/full-demo.md. Current runtime database/configuration untouched.
